# 交互校对与正式字段扩展

本次升级在原项目 `D:\JavaProject\master` 中完成，继续使用Java、Vue、MySQL及线上DeepSeek API。正式数据不因升级自动增加字段或改变值；由你在运行时选择需要的字段。

## 聊天中的折叠处理过程

助手消息上方的“处理过程与依据（摘要）”可以展开，显示请求识别、字段读取、后端校验、待补充、实际执行结果。内容根据实际发生的服务端事件生成，便于判断目前是否执行、为什么等待确认。

这里展示公开的处理摘要，不展示或保存模型内部思维链。上游即使返回`reasoning_content`也不会转发到页面。当前模型调用保持关闭thinking，使用工具调用。

## 日常使用

1. 在聊天中描述操作、粘贴多行数据，或使用“批量处理”“Excel导入”。
2. 遇到别名、缺值、重复列或额外字段时，打开“校对、补全并继续”。每列选择准确对应的字段；`id`、`stuID`、`name`等只作为建议，必须确认。
3. 同义列出现多列时，明确选择保留哪列，其他列选择忽略或映射成不同字段。系统不会自动丢列或合并。
4. 缺少学号等必要列时可添加空列，逐行填写；能找到相同姓名时提供现有学生候选。同名学生不会自动选中。
5. 表格中直接修正问题值，或采用系统提出的格式建议。也可排除明确不处理的行；全部问题解决后才能确认执行。
6. 核对最终预览并点击“确认执行本次操作”。结果逐行展示；执行时出现并发冲突会提示失败，可仅修正失败行后重试。

可以继续在聊天中回复，例如“确认stuID就是学号，name就是姓名”“保留第一列id，忽略第二列stuID”“不是新增，是修改已有学生”。模型读取同会话草稿后提出修正；不确定的值仍需追问，最终写入通过页面按钮明确确认。

关闭校对窗口会保留服务端草稿1小时。未保存的本地编辑会提示；聊天卡片可再次打开。重启应用会清空会话和未完成草稿，已确认保存的数据库值保留。

## 新增正式字段

额外列可以选择“新增正式字段…”，确认名称和类型。字段名称不可重复。最多20个自定义字段，核心学号和姓名保持不变。

| 类型 | 输入与存储要求 |
|---|---|
| 文本 | 非空，最多255字符；编号、电话等含前导零信息应选文本 |
| 整数 | 有符号64位整数；API通过字符串传递，保留大整数精度 |
| 小数 | MySQL DECIMAL(20,6)，整数部分最多14位、小数最多6位；API通过字符串传递 |
| 日期 | yyyy-MM-dd；无效日期会阻止保存，其他格式仅提出转换建议 |
| 是／否 | true/false；界面提供“是/否”选项，0和false不会误判为空 |

流程必须完成以下步骤：

1. 修正本批输入中所有待新增字段的值。
2. 逐条补齐数据库中**所有已有学生**的每个新字段，全部必填，不接受统一默认值或留空。当前导入行若对应已有学生且明确提供了值，可作为该学生的补全值显示供核对。
3. 数据少时直接填写补全表；数据多时下载全体学生补全Excel，填写后上传。上传文件也先识别列、修正问题，再将值合并回主草稿；此时仍未写库。
4. 点击“确认新增字段并保存全员补全值”，才执行正式字段变更。确认前若名单或任一数据变化，会阻止迁移；刷新名单后按学号保留已填值，再补新出现的学生。
5. 字段保存后，再确认本批学生新增或修改。两次确认分别表示不同操作；此时取消本批操作不会撤销已保存的新字段及补全值。

新字段在Navicat中是`student`表的真实列，内部列名为`f_...`，中文名称与类型保存在列注释中。传统列表、编辑表单、条件查询、Excel模板及AI工具都会读取最新字段。

## 常见异常如何处理

| 情况 | 处理方式 |
|---|---|
| id/name/stuID等别名 | 规则或模型提出对应关系，用户确认 |
| 学号/姓名等必需列缺失 | 添加空列，填写或选择候选学生 |
| 同名、大小写或格式接近的学号 | 显示候选/清理建议，用户决定 |
| 相同含义的多列 | 要求逐列选择，不自动取第一列 |
| 新列、未命名列 | 选择现有字段、新增正式字段或明确忽略 |
| 重复学号 | 修改、排除，或明确选择只保留第一条 |
| 新增时学号已存在 | 询问是否改为更新/新增或更新，原数据不直接覆盖 |
| 更新/删除/查询的学号不存在 | 修改学号、选择候选、改变操作或排除 |
| 删除时姓名与学号不符 | 要求核对并修正目标 |
| 日期、布尔、数字格式不符 | 提示原因与可用转换建议，采用建议后重新校验 |
| Excel公式或错误单元格 | 不计算公式，要求填写真实值或排除 |
| Excel数字超过15位精度 | 不猜测丢失数字，要求从原始资料填写文本值 |
| 工作表/表头选择错误 | 重新选择并读取原文件；先提示会替换编辑 |
| 其他窗口已更新草稿 | 版本冲突，刷新后再操作 |
| 预览后数据发生并发修改 | 不覆盖新值，返回逐行失败；修正失败行后重试 |
| 补全文件对应主任务已取消/字段已变 | 阻止合并，返回最新主任务重新处理 |

## 数据与权限

字段扩展不在普通事务里直接ALTER生产学生表。系统创建暂存表，加入新列，锁定并核对原表快照，填充全部旧数据及补全值，最后原子切换表名。切换前任何失败保留原表；切换成功保留`student_backup_...`升级前备份。不会自动清理这些备份表，管理员核实后自行处理。

本机专用3307实例首次启动会使用既有管理员配置，为项目账号在**本项目数据库内**启用结构迁移权限，不更改3306实例。需要SELECT、INSERT、UPDATE、DELETE、CREATE、ALTER、DROP、INDEX、LOCK TABLES、TRIGGER；其中TRIGGER用于准确检查依赖，发现触发器时拒绝自动迁移。只授权表结构相关操作，应用仍只能调用白名单业务接口。

其他MySQL实例由管理员对对应账号的项目库授予上述权限。例如先替换下面占位名称并检查目标库：

```sql
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX, LOCK TABLES, TRIGGER
ON `你的项目库`.* TO '你的项目账号'@'你的连接来源';
```

## 当前边界

- 仅考虑本地运行，未提供多用户身份认证、权限管理或对外部署。
- 文本最多30000字符；学生批次最多500行、最多50列；Excel最多2MB。补全文件每次最多10000行，可分批上传合并；全员补全名单当前整体载入内存，尚未针对超大数据量优化。
- 只支持新增字段；字段删除、改名和已有字段类型变更暂不提供。发现外键或触发器等表依赖时拒绝自动迁移，由管理员处理。
- 草稿、会话、请求去重保存在内存，重启后清空；学生数据和正式字段保存在MySQL。
- Excel在Java本地解析；主动请求DeepSeek推测时发送列名与少量样例，聊天纠错发送必要的前20行摘要，不发送完整工作簿。
- 系统覆盖常见歧义与错误，不会在无法确定时替用户编造学号、姓名或其他字段值。
